# NEXUS — Design Tokens

Derived from the two finalized Figma files and the `design_system` block of
`product/Nexus_CRM_Master_Spec_v1.json`.

> **Source of truth order.** The JSON spec owns behaviour, data invariants,
> permissions, integrations and acceptance criteria. Figma owns visual layout,
> spacing, hierarchy, typography, control placement and design language.
> Where the two appear to conflict, the JSON wins on behaviour and the Figma
> design language is preserved.

## Visual direction (spec `design_system.visual_direction`)

Light/off-white surfaces · cool gray structure · electric cyan and restrained
indigo accents · thin 1px borders · generous but compact operational spacing ·
subtle technical/sci-fi feel, never a dark gaming dashboard · Inter · clear
cards, chips, compact tables, simple buttons and status pills.

## Implementation notes

- The concrete hex values for the accent scale live in
  `packages/ui/src/tokens.ts` as the single source consumed by both the web app
  and the extension, so the two surfaces cannot drift.
- `packages/ui/src/tokens.ts` is generated by hand from the spec + `.fig`
  measurements, and every value carries a `provenance` field naming where it
  came from (`SPEC` or `FIGMA` or `ASSUMPTION`).

### ASSUMPTION (recorded, not silent)

The `.fig` containers are `fig-kiwi` binaries. Three inputs are derived from the
spec rather than measured from the binary and are marked `ASSUMPTION` in
`tokens.ts`:

1. Exact accent hex values (the spec names the accent *semantics* and the
   `.fig` files are the visual authority, but accent chip fills are inside
   nested node styles rather than the frame background).
2. Exact type ramp px sizes beyond the reference surfaces.
3. Exact spacing scale steps.

The `.fig`-measured values (canvas colour, reference surface sizes, sidebar
widths, radius range, border width, primary button treatment) are used verbatim
and are marked `SPEC` / `FIGMA`. Any later refinement of the `.fig` decoder can
replace the `ASSUMPTION` rows without touching component code, because all
components read tokens by name.
